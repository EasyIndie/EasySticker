# 使用手册

> 本文讲**功能怎么用**：创建、生成、导入、编辑、还原、下载。
> 部署与配置见 [部署指南](deployment.md) / [配置参考](configuration-reference.md)，
> 产物格式见 [包格式](pack-format.md)。

---

## 1. 核心概念

| 概念 | 含义 |
|------|------|
| 平台预设（preset） | 决定数量、交付尺寸、输出格式与是否生成扩展资源 |
| 参考图 | AI 生成的主体依据；可以是上传图，也可以是 AI 生成的图 |
| 提示词预设 | 内置的成套内容模板，可与自定义提示词追加或覆盖组合 |
| 风格 | 决定画面表现；风格描述统一由配置注入 |
| 表情包（pack） | 一次生成或导入的结果，包含主表情、扩展资源、参考图与 `metadata.json` |
| 下载 / 打包 | 服务端只存素材与清单，ZIP 在下载时现场打包 |

完整产物结构见 [包格式](pack-format.md)。

---

## 2. 创建方式

首页第 1 步先选创建方式和目标平台：

| 创建方式 | 适合场景 |
|---------|---------|
| **AI 生成** | 有角色参考图（或想用文字先生成参考图），希望批量生成新表情 |
| **导入已有图片** | 已有成品图，只需要标准化、补扩展资源、打包 |

选择 AI 模式后，第 1 步还会出现 **AI 提供商**选择器。它同时决定参考图生成与整包表情生成所使用的模型。

平台差异：

| 平台 | 数量 | 交付规格 | 扩展资源 |
|------|------|---------|---------|
| 微信 | 8–24 张 | 240 × 240 PNG | 封面 / 图标 / 横幅 / 赞赏图 |
| Telegram | 1–50 张 | ≤ 512 × 512 PNG | — |
| WhatsApp | 1–30 张 | 512 × 512 WebP | — |

## 3. 用 AI 生成表情包

### 3.1 准备参考图

第 2 步提供两种方式：

1. **上传参考图**：可选。建议主体清晰、边缘完整，支持 PNG / JPG。
2. **AI 生成参考图**：填写「描述主体」，不选底图即文生图；可选一张主底图，最多再加 3 张附加参考图走图生图。

AI 生成的参考图与上传图等价，都会作为整包生成的主体依据。两者都不提供时，
系统会按提示词走纯文生图；已经有成品图时，也可以直接用其中一张作为参考。

### 3.2 配置提示词与风格

第 3 步包含：

- **提示词预设**：内置多套内容模板（当前清单见
  [配置参考](configuration-reference.md#45-promptpresets)）。部分预设自带推荐风格，
  选中后会自动切选。
- **提示词自定义**：可留空。与预设组合方式由「自定义用法」决定：
  - **追加**（默认）：最终提示词 = 预设 + 自定义；
  - **覆盖**：忽略预设，只用自定义。
- **风格选择**：内置多种风格（当前清单见 [配置参考](configuration-reference.md#41-global)）；
  风格描述由 `global.stylePrompts` 统一注入，预设不重复写画风。
- **贴纸数量**：受平台上下限约束。
- **元数据**：标题、作者必填；版本、版权可选。
- **赞赏功能**（仅微信）：开启后额外生成赞赏引导图与答谢图，需要填写引导语。

提示词与风格共同决定生成结果；改文案或换风格后，建议先用少量张数试跑。

### 3.3 生成与进度

点击生成后，服务端通过 SSE 逐张推送进度。生成过程中：

- 已成功的图片会立即出现在预览区，不会因为后续失败而被清空；
- 每张图都可以单独重新生成；
- 可以取消任务。

### 3.4 预览、编辑与下载

预览卡片上会标注该图实际使用的提示词、情绪与风格：

- **重新生成**：只重做当前这一张；
- **编辑图片**：以当前图为源，填写修改要求后只生成一个新版本，可再附一张参考图；
- **版本**：查看该图的历史版本并回退（回退只移动当前指针，不新增版本）；
- **下载 ZIP**：按当前清单现场打包，包含主表情、扩展资源、参考图、历史版本与 `metadata.json`。

微信 AI 模式默认补齐封面、图标与横幅；微信导入模式会自动从第一张图生成封面和图标，
横幅与赞赏图需要手动提供。

## 4. 导入已有图片

### 4.1 批量导入成品图

第 2 步选择「批量导入成品图片」：

1. 选择 PNG / JPG / WebP / GIF（可多选）；
2. 微信可额外上传封面、图标、横幅、赞赏引导 / 答谢图；
3. 系统统一居中、等比缩放、补透明边，并转换为平台交付格式；
4. 填写标题、作者等信息后打包下载。

微信导入时，未提供封面会用第一张表情生成，未提供图标会从封面或第一张图生成；
横幅与赞赏图不会凭空生成。

### 4.2 补齐剩余表情（AI 或上传）

导入或生成过一部分图片后，如果还需要补齐剩余表情：

1. 在预览区「表情主图」标题旁点击 **补齐**；
2. 在同一个补齐流程里选择 **图片来源**：
   - **使用已有图片**：从当前表情包中选一张图；可点击下拉列表选择，也可用 **↑ / ↓** 快速切换；
   - **上传新图片**：从本地选择图片；
3. 再选择 **处理方式**：
   - **AI 生成新图**：以所选图片为参考，填写补齐张数与内容描述；风格可选，不选时不写入任何风格描述。
     图片来源是「上传新图片」时，上传图只作为本次 AI 参考图；
   - **直接使用原图**：仅在上传新图片时可用。图片按当前平台规格自动规范化后直接补进表情包，
     可一次上传多张；不做 AI 重绘。
4. 系统把结果**追加**到当前表情包，不会覆盖已有图片；
5. 完成后会自动重建同一份包，可直接预览、继续补齐或下载 ZIP。

上传原图补齐时，微信主图会规范为 240×240 PNG，Telegram 为 512×512 PNG，
WhatsApp 为 512×512 WebP；封面 / 图标 / 横幅 / 赞赏图会按各自固定尺寸补边或裁切。
作为 AI 参考图上传的图片只用于这一次生成，不会原样写进包内，也不会替换整包的参考图。

AI 或上传补齐生成的图片卡片上会多出 **重新补齐** 入口：对结果不满意时，可以换 AI 参考图、
上传新图、提示词或风格再补一次；旧版本会保留在「版本」历史中，可随时回退。

每张图片卡片上还有 **删除** 入口，可把不满意的成品从当前包里移除，便于筛选高质量作品。
删除主表情后序号会自动重排；低于平台最低数量时会提示，可用补齐补足。
删除只是把素材移出当前包，不会立即删磁盘文件（由后台 GC 回收）；如需恢复，可重新导入原图或重新生成。

预览区中显示 **待补齐** 的封面、图标、横幅或赞赏图也可以直接点击：
选择图片来源与处理方式后，只会补齐这一张空白资源，不影响已有表情。

即使原包没有「上传的参考图」，预览卡片上的 **编辑图片** 和 **重新生成** 仍然可用：
编辑以当前图为准，重新生成会回退到包内已有图片作为参考。

### 4.3 用 ZIP 还原生成现场

选择之前从本站下载的 ZIP，系统会读回：

- 提示词预设 / 自定义文本 / `promptMode`；
- 风格、情绪、参考图；
- 每张图的提示词与历史版本；
- 生成上下文（提供商、模型、尺寸等）。

还原后可以继续单张重新生成、编辑、补齐（AI 或上传），或改提示词重做整套。

## 5. 历史记录与还原

- **已登录用户**：历史存服务端，按邮箱归属，换设备也能找回。
- **未登录用户**：按浏览器持久化的 `x-client-id` 尽力保留；清空浏览器数据会丢失关联。
- **还原现场**：历史记录中的「还原现场」会恢复创建方式、AI 提供商、预设、自定义提示词、
  `promptMode`、风格与数量，而不只是图片。
- **编辑不新增历史**：重新打包会带上原 `packId`，服务端原地更新同一份清单，避免记录越编辑越多。

## 6. 管理后台

管理员登录后可进入 `/admin.html`：

| 标签页 | 能做什么 |
|--------|---------|
| 仪表盘 | 实时指标（SSE）、当前告警、资源概况 |
| 用户 | 查看用户、停用 / 启用、硬删除（可选清理其数据） |
| 统计 | 请求吞吐、延迟、CPU / 内存图表、接口热点与用户用量 |
| 存储 | 查看占用与包列表、批量删包并立即回收素材、手动触发巡检 |
| 设置 | AI 提供商与密钥、通知 / 告警规则、监控保留期等运行期配置 |

管理员账号受保护，不能被停用或删除。停用 / 删除后，该账号已签发的 JWT 立即失效。

## 7. 常见使用问题

**生成结果一直是随机图？**
`ai.defaultProvider` 仍是 `mock`，或没有配置可用的 API Key。

**某张图不满意，必须整包重跑吗？**
不需要。在预览卡片上单张重新生成，或使用「编辑图片」只改这一张。

**先导入了几张成品，能只让 AI 生成剩下的吗？**
可以。导入后在预览区「表情主图」标题旁点击「补齐」，选择「AI 生成」，用包内已有图片作参考，
填写数量与内容即可追加生成。也可以切换到「上传图片」，把现成成品图直接补齐进包。
编辑已有图片也不要求原包必须有上传的参考图。

**导入 Telegram / WhatsApp 时被提示「至少 8 张」？**
这是旧版本的问题，已在后续版本修复。确认导入请求带上了正确的 `presetId`。

**下载的 ZIP 里为什么没有 `history/`？**
只有被编辑或重新生成过的图片才有历史版本；未编辑过的图不会生成该目录。

**历史记录里找不到以前的包？**
未登录历史依赖浏览器标识；换浏览器 / 清数据后可能丢失。登录后历史按邮箱存服务端。
