EasySticker 设计规范页

沉淀首页流程、视觉层级、表单帮助文案与交互反馈规则，确保后续新增页面仍然遵循同一套令牌和可访问性约束。

该页面聚焦规范定义，不替代自动化验证结果；兼容性结论与性能基线统一收敛到专项报告页。
Principles

设计原则

  • 以单页四步流程为核心，优先保证上传、编辑、生成、下载的线性可理解性。
  • 优先使用语义令牌，不在业务组件里直接写死颜色、间距或圆角。
  • 帮助文案与错误文案分层管理，字段解释通过 aria-describedby 与控件绑定。
  • 结果概览与导出信息默认折叠，兼顾扫描效率与高密度信息展示。
Layout

布局基线

  • 页面主容器最大宽度 980px，外边距居中，移动端统一回落到单列栅格。
  • 主流程卡片使用 16px 内边距、14px 圆角与中等阴影，保证层级稳定。
  • 预览区、资源区与文档区共享同一套卡片容器模式，避免视觉碎片化。
  • 操作区按钮按主操作、次操作、信息跳转三层优先级排列。
Token Usage

令牌使用约束

Action Tokens --color-primary / --color-primary-soft / --color-primary-border 用于主按钮、选中态样式芯片与成功路径强调。
Info Tokens --color-info / --color-info-soft / --color-info-border 用于信息面板、导出确认区、聚焦与辅助说明。
Danger Tokens --color-danger / --color-danger-soft / --color-danger-border 用于错误摘要、字段校验、失败状态与风险提示。
Surface Tokens --color-surface-primary / secondary / tertiary / elevated 用于页面背景、卡片分层、棋盘预览承载与文档容器。
Form Help

帮助文案策略

  • 上传控件说明文件格式、主体建议与作用域，降低错误上传概率。
  • 提示词帮助文案强调主体、情绪、动作与背景限制四项核心信息。
  • 版本、版权与赞赏开关均提供场景化说明，减少字段用途歧义。
  • 必填字段错误文案使用明确动作词，例如“请填写”“请至少选择”。
Feedback

反馈层级

  • 顶部 notice 用于当前阶段主提示，toast-notice 用于短时操作结果反馈。
  • status-chip 展示流程状态，error-summary 聚合阻断性输入问题。
  • export-info 与 metadata 面板用于下载前的二次确认。
  • 预览卡和资源卡在空态、加载态、错误态复用统一描述句式。
Keyboard

键盘操作速查表（简版）

  • 风格芯片：左右/上下箭头移动焦点；Home/End 快速跳首/跳尾；Enter/空格切换选中；至少保留 1 种风格。
  • 生成快捷键：Ctrl + Enter 在生成表单内快速触发生成（遵循必填校验）。
  • 跳到主要内容：Tab 聚焦左上角“跳到主要内容”后按 Enter 跳转到主区域。
Extension Rules

新增页面扩展规则

  • 新增页面先复用 hero、card、notice、docs-grid、token-card 等基础结构。
  • 若出现新状态色，先在 styles.css 增加语义 token，再扩展组件 tone。
  • 新增表单字段时，同步补充 hint、error 容器、aria-describedby 与测试断言。
  • 新增文档页与报告页时，导航需保证从首页、组件库页和目标页之间可互相跳转。
  • 新增性能或质量报告时，建议同时补充基线说明、对比区间与可复现的采样口径。
