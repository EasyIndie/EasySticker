Principles

设计原则

  • 以单页主流程为核心，优先保证上传、导入、生成、预览、下载的线性可理解性。
  • 主流程不展示内部工程页面入口，避免普通用户分心。
  • 页面主容器最大宽度 980px，窄屏统一回落到单列布局。
  • 新增控件先复用语义 token、card、notice、summary-card、preview-item 等基础模式。
Forms

表单与文案规则

  • 必填项必须同步提供 hint、error 容器、aria-describedby 与错误摘要映射。
  • 提示词说明聚焦主体、情绪、动作、背景限制四类信息。
  • 导入模式与 AI 模式共享标题、作者、版权、赞赏信息和结果展示。
  • 错误文案使用明确动作词，例如“请填写”“请上传”“请至少选择”。
Quality

兼容性与回归检查

检查项 基线 当前结论 说明
桌面 Chromium Chrome / Edge 新版 通过基线 主流程、内部页、Swagger 均可加载。
移动端布局 720px 以下单列 通过基线 卡片、表单、预览区使用响应式约束。
键盘与可访问性 Tab / Enter / aria 通过基线 保留跳转链接、错误摘要、字段回跳和 focus ring。
自动化回归 npm test 提交前运行 覆盖 provider、配置、主流程、导入、懒加载 adapter 等核心路径。
  • 主流程重点验证：AI/导入切换、必填校验、生成取消、结果恢复、ZIP 下载。
  • 本地 ComfyUI 路径重点验证：懒启动、离开取消、空闲停止、退出清理。
  • 后续若引入拖拽上传、动画或图表，需要补充专项兼容性用例。

Keyboard

键盘操作速查表 / Keyboard Cheatsheet

  • 风格芯片：左右/上下箭头移动焦点；Home/End 快速跳首/跳尾；Enter/空格切换选中；至少保留 1 种风格。
  • 生成快捷键：Ctrl + Enter 在生成表单内快速触发生成（遵循必填校验）。
  • 跳到主要内容：Tab 聚焦左上角“跳到主要内容”后按 Enter 跳转到主区域。
